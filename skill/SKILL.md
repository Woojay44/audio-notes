# 课堂录音 → 文字 → 笔记 → Obsidian

**先读同目录的 `local.md`**（本机配置：项目目录、当前学期、Obsidian 库位置、课程表、格式范例）。没有这个文件就让用户照 `local.example.md` 建一个。下文的 `<项目>`、`<库>` 都指 `local.md` 里写的路径。

转写在 WSL 里用 faster-whisper 本地运行（GPU），免费，录音不上传。

## 1. 输入

- **用户每次会说明：科目、第几周**。学期见 `local.md`。没说科目或周次就先问，不要猜：m4a 里的 creation_time 往往是导出时间，不是上课时间。
- **收件箱 = `<项目>` 根目录**：根目录里的音频文件就是待处理的。处理完移到 `audio\`，保持根目录干净。
- 手机录音的文件名通常看不出内容和先后顺序，以转写内容为准。

## 2. 转写

```bash
MSYS_NO_PATHCONV=1 wsl.exe -e bash <项目的 WSL 路径>/transcribe.sh '<项目>\xxx.m4a' [...] --terms '术语1,术语2,...'
```

- 在 Git Bash 里调用时 `MSYS_NO_PATHCONV=1` 不能省，否则 `/mnt/d/...` 会被改写成 Windows 路径。
- 用 Bash 工具后台运行，多个文件一次传进去（只加载一次模型）。45 分钟录音约 1–4 分钟。路径用单引号。
- `--terms`：用课程表里的术语；新课程就取课程名加 5–10 个核心术语（含英文），能减少同音错字。
- 输出：`transcripts\<原文件名>.txt`，按停顿分段，每段一行 `[hh:mm:ss] 文本`。已存在会跳过，`--force` 重转。
- 检查转写稿是否覆盖到音频结尾、有没有长时间空白，然后把音频从根目录移到 `audio\`。

## 3. 读转写稿

- 每份**从头读到尾**，不要只读开头就下结论。
- 同一节课常被拆成几段录音（课间断开），先理清每段讲了哪些主题，再按主题归并。
- Whisper 会把专业术语听成同音字（"零知识证明"→"预计证明 / 临时证明"），根据上下文改正。实在确定不了的不要编造，放进笔记末尾的"待核对"。
- 课上放的视频片段会混在稿子里（语气突然变成科普口吻），要和老师自己讲的内容区分开。
- 留意老师说"会考 / 要记 / 一定要来 / 不考"的地方，课堂练习题也要记下来。

## 4. 写笔记，放进 Obsidian

- 目录：按 `local.md` 的课程表放进 `<库>\<学期>\<课程>\`。新课程就新建目录，并在 `local.md` 的课程表里加一行。
- **一个主题一份笔记**：按知识主题（章节）组织，不按录音分。同一主题跨多段录音的合成一份；一段录音讲了两个主题就拆成两份。
- 文件名：`<课程>-第N周-<主题>.md`，周次用中文数字（如 `计算机网络-第三周-传输层.md`）。
- 同主题的笔记已存在（上周没讲完）：读出来，把新内容**融进对应章节**，不要另起一份，也不要直接覆盖。
- 能链接到库里已有笔记的，在"相关笔记"里加 wikilink。先 `find` 确认目标存在。
- **笔记里不写录音时间戳，正文不标（？）**。转写稿（带时间戳）留在 `<项目>\transcripts\`，不进 Obsidian；用户问原话时去那里找。

### frontmatter

```yaml
---
课程: <课程>
学期: <学期>
周次: 第N周
章节: <主题>
类型: 课堂笔记
来源: 课堂录音整理
状态: 已整理
tags:
  - <学期>
  - <课程>
  - 课堂笔记
  - <2–4 个主题标签>
aliases:
  - <主题>
---
```

### 格式：专业、好看，像教材笔记，不像录音流水账

`local.md` 里有格式范例的话，先读一遍再照它的风格写。要点：

- 按**知识逻辑**重新组织，不按老师讲课的顺序。闲聊、跑题删掉；有价值的科研 / 升学建议放进文末折叠的 `> [!quote]-` 框。
- 中文章节编号：`## 一、` / `### 3.1`。
- Obsidian 元素用到位：
  - `[!abstract]` 本章概览，`[!note]` 定义，`[!important]` 考点 / 原则，`[!tip]` 记忆法 / 拓展，`[!example]` 例子，`[!warning]` 易错 / 争议；
  - 对比类内容用表格；
  - 流程和协议用 mermaid（`sequenceDiagram` / `flowchart`），知识框架用 `mindmap`；
  - 公式用 `$…$`。
- 老师明确说"会考 / 要记 / 一定要来"的，在开头放一个 `[!important] 老师明确的考点` 框。
- 老师的说法和标准教材有出入时，用 `[!warning]` 写清两边，提示"考试按老师口径"。
- 自己补充的背景知识放进 `[!tip] 拓展`，和老师讲的内容区分开。

```markdown
# <课程>-第N周-<主题>

> [!abstract] 本章概览
> [!important] 老师明确的考点   （有才写）
## 一、学习目标
## 二、知识框架        （mermaid mindmap）
## 三、… 正文各节      （定义框、对比表、流程图）
## X、考点速记         （表格）
## X、复习题
> [!faq]- 待核对      （录音不清处，折叠）
> [!quote]- 课堂延伸  （可选，折叠）
## 相关笔记
```

### 复习题

每份 8–14 题，覆盖考点速记里的每一项。题型混合：概念辨析、判断题（老师课上的练习题优先）、过程复述（协议步骤）、计算、开放思考。答案用可折叠 callout，先自测再展开：

```markdown
> [!question] 1. 为什么说密码方案的安全性归根结底来自密钥？
>
> > [!success]- 答案
> > ……
```

## 5. 交付

- 交付前用脚本检查：wikilink 都能解析，正文没有残留的时间戳 `[hh:mm:ss]` 和"（？）"，frontmatter 完整。
- 回复里给出：笔记路径、每份笔记的几行要点、老师明确的考点、"待核对"里需要用户对照课件的地方。
- 用户追问细节时，到转写稿里找原话回答。
